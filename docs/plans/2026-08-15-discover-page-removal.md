# 计划：删除小程序发现页（及专属前后端代码）

日期：2026-08-15
作者：CodeBuddy（superpowers:writing-plans）

## 目标

1. 删除小程序「发现页」页面本身。
2. 删除仅服务于发现页的前端代码（入口配置、页面类型、搜索 API 封装）。
3. 删除仅被发现页调用的后端代码（搜索路由 + 搜索匹配库 + 已孤儿化的类型）。

原则：**只删「发现页专属」代码，保留被其它页面复用的代码**（如 `getUserProfile`、`tag-search`、`pinyin`、匹配接口 `MatchCircleDTO`/`PublicUserProfileDTO` 等）。

## 任务分解

### Task 1 — 删除后端发现页专属代码
**1.1 删除路由文件**
- `rm admin/app/api/users/search/route.ts`
- `rm admin/app/api/circles/search/route.ts`
- 同时移除其所在目录（若变空：`admin/app/api/users/search/`、`admin/app/api/circles/search/`）

**1.2 删除匹配库**
- `rm admin/lib/search/user-search.ts`
- `rm admin/lib/search/circle-search.ts`

**1.3 清理后端孤儿类型**（`admin/types/api.ts`）
删除第 161–211 行（从 `UserMatchedField` 注释起到 `SearchQueryParams` 闭合 `}` 止），保留前后的 `MatchCircleDTO` 与 `PublicUserProfileDTO`。

```diff
   }
```

### Task 3 — 删除前端发现页专属类型与 API 封装
**3.1 删除 `src/types/index.ts` 的搜索类型块**（第 188–228 行）
```diff
   // ============ 发现搜索业务类型 ============
-  export type UserMatchedField = ...
   ... (整块删除) ...
-  export type SearchQueryParams = ...
```
（该块仅被 discover 与 `api/search.ts` 引用，删除后对其它类型无影响。）

**3.2 精简 `src/api/search.ts`**
- 删除 `searchUsers`、`searchCircles` 两个函数及其实现；
- 删除顶部已失效的 import（`UserSearchResultDTO`、`CircleSearchResultDTO`、`SearchQueryParams`）；
- **保留** `getUserProfile` 及 `PublicUserProfileDTO` 的 import（被 `user-home` 使用）。

保留后的文件顶部 import 大致为：
```ts
import request from "./request"
import type { PublicUserProfileDTO } from "@/types"

/** 获取用户主页公开信息(用于用户主页 user-home 等) */
export function getUserProfile(userId: string) {
  return request.get<PublicUserProfileDTO>(`/api/users/${userId}/profile`)
}
```

**验证**：`cd frontend_uniapp && pnpm type-check` 通过；`pnpm test:run` 前端单测通过。
